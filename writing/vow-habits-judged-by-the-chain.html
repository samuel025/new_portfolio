Vow: Money Habits Judged
by the Chain, Coached by Memory

How I built an agent that reads real Sui transactions through Tatum to decide whether you kept a commitment, then remembers every outcome in Walrus Memory and uses that history to pick the next nudge.

— Habit apps run on honesty: you tick a box and the app believes you. For money habits the evidence is already public. Vow reads your wallet's real Sui mainnet transactions to decide kept, missed or unverified, stores each outcome in Walrus Memory, and lets that memory change how it nudges you. It never holds or moves your funds.

The Problem: Habit Apps Run on Honesty

Most habit trackers are a checkbox with a streak counter on top. The streak is only as truthful as your worst day, and apps that put money behind a habit have the same weakness, because the check-in is still something you report about yourself.

Money habits are different. If your vow is "send at least 5 SUI to my savings address every Friday", the answer is sitting on a public chain. Nobody needs to ask you. Vow was built around that idea: the chain is the judge, and memory shapes the nudge.

How Vow Works

The loop has four stages, and only the last one uses anything like intelligence:

  • Watch: fetch the wallet's recent sent transactions (balance changes and Move calls) from Tatum's Sui gateway.
  • Verify: a deterministic verifier compares them to the vow's rule and the week's window and returns kept, missed or unverified, with the reason in plain English and the qualifying transaction digests.
  • Remember: write one compact record per window to Walrus Memory: habit, weekday, result, and the nudge that came before it.
  • Nudge: before the next window, recall that history and pick the reminder style and tone that actually worked for this person.

Vow supports four habit types: recurring save, spend cap, quiet hours and recurring stake. If the chain can't be reached, the window is marked unverified. It is never silently counted as a miss.

What Tatum, Sui and Walrus Each Do

  • Tatum is the eyes. Every verdict starts with a call to the Sui mainnet GraphQL gateway, authenticated with an x-api-key. Tatum is the only source of chain truth in the app.
  • Sui is the ledger and the identity. The vows are about real SUI and USDC transfers and staking calls. Wallet sign-in uses the Sui Wallet Standard: you sign one off-chain message, no transaction and no gas, and the server verifies it (zkLogin accounts included). Walrus Memory is anchored to a MemWalAccount object on Sui.
  • Walrus Memory is the brain. Records are written with remember, brought back with recall before every nudge, and listed with listMemories on a Proof page that shows each blob's storage end epoch.
// What the watcher asks Tatum for (simplified)
query($a: SuiAddress!, $c: UInt53) {
  transactions(last: 50, filter: { sentAddress: $a, afterCheckpoint: $c }) {
    nodes {
      digest
      effects { status timestamp balanceChanges { nodes { owner coinType amount } } }
      kind { ... on ProgrammableTransaction { commands { nodes { ... on MoveCallCommand { function { name } } } } } }
    }
  }
}

Memory That Changes What the Agent Does

Storing history isn't the interesting part. Using it is. Each record keeps the nudge sent before its window, so the record's result is that nudge's outcome. When the next window comes around, the nudge engine scores each style and tone by how often a kept window followed it, tries untested ones first, and, when most of your misses land on one weekday, proposes moving the day.

A "Why this nudge?" panel shows the records behind every choice and says whether the choice was learned from your history or is just exploring because there isn't enough data yet. That distinction matters, because it keeps the agent from claiming a pattern it hasn't earned.

— The same recalled records power the coach's answers, the ghost race (your latest windows against the ones before them) and the streak and freeze logic. Remove Walrus and the agent has only a local file on one machine, with nothing durable, portable or publicly provable.

The Verifier Never Uses an LLM

This was a deliberate line. A language model does two small jobs in Vow: it phrases coach answers from the memory records you hand it (with [n] citations resolved back to real records), and it drafts a vow from a sentence like "save 20 USDC to 0x… every Thursday", which you review before anything is saved. It never decides a result. Kept, missed, streaks, XP and nudge choice are all plain code over chain data and memory, so a verdict can be checked by anyone with a block explorer.

The benchmark deserves a warning label. The simulated users have hidden response rates I chose, so the result shows that the nudge logic can learn a pattern when one exists. It says nothing about real behaviour change, and the app labels any simulated history as such.

Problems I Ran Into

  • Tatum's Sui endpoint is GraphQL, not JSON-RPC. The root path returned 404 for RPC calls. I moved to the GraphQL gateway, learned its retention window from the "lowest available checkpoint is N" error, and retried with afterCheckpoint.
  • Walrus writes take seconds. Blocking on them made the UI feel broken. Records now go to a local mirror instantly and to Walrus in a background job, with cached recalls and a timeout.
  • Failed transactions looked like evidence. A failed staking call would have counted as kept until I filtered on each transaction's on-chain status.
  • Units. SUI is 1e9 and USDC is 1e6. Get that wrong and every save looks missed.

Limits & Tradeoffs

  • Only one wallet is visible. A spend cap can't see other wallets, exchanges, cards or cash, so "kept" means this wallet stayed within the rule, not that you spent less overall.
  • Walrus namespaces are public. Memory records hold habit names, results and styles, never amounts, tokens or addresses, and the app tells users to keep names generic. Records expire at their end epoch.
  • Short history. Tatum serves recent Sui history only, so Vow records what it sees as it goes.
  • Demo scale. Data lives in local JSON files and all wallets share one delegate key and namespace. That is fine for a hackathon and wrong for production.

Conclusion & Source Code

Vow shows that a habit agent doesn't have to trust the user or the model. The chain establishes what happened, and memory informs what to do next. Tatum, Sui and Walrus each carry a job the app can't do without.
